# CanvasTTY Accounts

[English](README.md)

Любой агент на любой модели. Запускайте **Claude Code, Codex, OpenCode, Qwen Code или Kimi** на выбранной модели —
локальной в Ollama, в Ollama Cloud, Z.AI, MiniMax, OpenRouter или любом API, совместимом с Anthropic или OpenAI, —
выбирая её при каждом запуске.

## Как пользоваться

1. Установите плагин и подтвердите его нативный код в **Настройки → Агенты → Extension native code**.
2. Откройте **Учётные записи моделей** (страница настроек плагина) и добавьте запись: провайдер (адрес подставится),
   название, модель, каким агентам её можно использовать. Для API сохраните ключ (только запись). **Проверить**
   показывает модели сервера Ollama на этом компьютере или проверяет формат сохранённого ключа — в платные API ничего
   не отправляется.
3. В окне запуска агента: **Дополнительно → Use CanvasTTY Accounts**, выберите **Model account**, при желании
   **Reasoning effort** и **I trust this folder**.

Оркестраторы получают два инструмента: `canvastty-accounts__list_routes` (все записи × агенты: готова или почему нет)
и `canvastty-accounts__pick_account` (первая готовая запись для агента, неработающие сейчас пропускаются). Оба
возвращают `launchOptions` для `spawn_agent`.

## Что меняется при запуске

- Claude Code: `ANTHROPIC_BASE_URL` (для Ollama — корень сервера), `ANTHROPIC_AUTH_TOKEN` (ключ или `ollama` для
  локального сервера), все уровни моделей = модель записи, `--model`, и адрес повторён в `--settings`, чтобы настройки
  проекта не могли перенаправить ключ. Claude работает в собственном `CLAUDE_CONFIG_DIR` записи в папке данных
  плагина, первичная настройка пропущена.
- Codex: провайдер только через `-c` (Responses API), каталог из одной модели в личной папке запуска, собственный
  `CODEX_HOME` записи, переменная ключа через `env_key`.
- OpenCode: личный файл `OPENCODE_CONFIG` (API Anthropic получают `/v1`), ключ как `{env:…}`.
- Qwen Code: `--auth-type openai` и `OPENAI_*`. Kimi: провайдер `openai_legacy` в `--config` (без ключа) или личный
  `--config-file`.
- Ollama на этом компьютере: модель закреплена как `имя:local`, поэтому сервер сам не отправит её в облако; перед
  запуском проверяется, что Ollama работает, модель установлена и умеет вызывать инструменты.

Ключи хранятся в зашифрованных секретах плагина; в окружение агента их кладёт сам CanvasTTY и маскирует во всём, что
читают другие агенты. В `~/.claude`, `~/.codex`, `~/.qwen`, `~/.kimi` и `~/.ollama` ничего не пишется, собственные
входы агентов для адреса записи не используются.

Нужен CanvasTTY с точками запуска для учётных записей (списки `optionsFrom`, `launchOptions` в `spawn_agent`, слияние
`--settings` для Claude).

## Разработка

`ESBUILD=/путь/к/esbuild node scripts/build.mjs` собирает `services/accounts.mjs` и `settings/accounts.js` и
обновляет манифест. `npm test` запускает тесты (с `CANVASTTY_REPO` — ещё и валидатор манифеста CanvasTTY).
